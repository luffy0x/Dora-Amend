# Dora Amend 演示视频脚本

目标时长：2 分 40 秒左右。

## 录制前准备

1. 运行 `pnpm dev`，使用普通演示模式，不加 `?study=1`。
2. 浏览器窗口建议设为 1440×900，缩放保持 100%。
3. 点击“重置演示”，选择“正常分析”，确认当前为 v1。
4. 录制时让鼠标停留片刻再点击，关键变化出现后至少停留 2 秒。
5. 不把 Mock 经营数字表述为真实业务数据，不声称已经完成用户验证。

## 分镜与旁白

### 00:00 至 00:15，命题与问题

画面：先展示完整工作台，再把视线带到回答标题和右侧证据区。

旁白：

> 当 Data Agent 给出一条经营结论，业务用户真正需要判断的，不只是答案是什么，还包括它用了哪些数据、哪些是事实或推断，以及发现口径错误后能否及时修正。Dora Amend 是为此设计的可信回答层。

### 00:15 至 00:35，先判断能不能信

画面：展示“华东区 7 月利润下降 18.7%”的初始回答，停留在可信摘要，依次指向数据来源、更新时间、分析范围、筛选条件和新店提醒。

旁白：

> 用户无需先读执行日志。回答顶部集中呈现数据来源、更新时间、分析范围与关键筛选，并主动提醒当前包含 7 家开业不足 90 天的门店。事实、Agent 推断和行动建议也被明确区分。

### 00:35 至 01:05，按结论追溯证据

画面：点击“上海门店客单价下降是当前识别的首要原因”，在右侧查看事实、计算、范围提醒与推断；展开一次“技术明细”，展示查询编号、字段、Mock SQL 和引用关系，再收起。

旁白：

> 对“客单价是首要原因”这条可疑推断，用户点击结论即可看到只与它相关的证据。系统说明客单价的原始变化、贡献度计算，也明确提示新店与成熟门店混在一起可能放大相关性。技术用户仍可按需查看可审计明细，但它不会成为普通用户的阅读负担。

### 01:05 至 01:35，就地纠正口径

画面：点击“核验并纠正”，展示修正意图和结构化条件“排除开业不足 90 天门店”，再点击“生成影响预览”。

旁白：

> 发现问题后，不必另开会话重新描述上下文。用户可以在当前结论旁发起纠正。自然语言不会立刻执行，而是先转换成可确认的结构化条件，避免系统误解修改意图。

### 01:35 至 01:55，确认影响并局部重跑

画面：停留在影响预览，指向“会更新”和“保持不变”；点击“确认并局部重跑”，完整展示三步进度。

旁白：

> 执行前，Dora Amend 告诉用户哪些事实、推断和建议会被重算，哪些数据来源与时间范围保持不变。确认后只更新受影响部分，并保留原回答作为 v1。

### 01:55 至 02:25，对比结论为何变化

画面：展示版本对比，再在 v1 与 v2 间切换。依次指向利润降幅、首要原因与建议的变化，最后点击“查看修订后证据”。

旁白：

> 修订后，可比门店利润降幅从 18.7% 收窄到 8.4%，首要原因从上海客单价变为履约成本率，行动建议也转向配送定价和补贴。版本对比不仅显示答案变了，还解释变化来自哪一项口径修正，原结论仍可随时回看。

### 02:25 至 02:40，异常与价值收尾

画面：快速切换“数据过期”和“权限不足”场景，各停留 2 至 3 秒，然后返回正常场景和全局画面。

旁白：

> 当数据过期、来源不可用或权限不足时，系统会暴露证据缺口，而不是用不完整信息制造确定答案。Dora Amend 不让用户无条件相信 Agent，而是让每个结论都看得懂、信得过、能追溯，也能被纠正。

## 录制完成检查

- 总时长控制在 2 分 30 秒至 3 分钟。
- 画面中没有账号、通知、浏览器书签或其他隐私信息。
- 全程只出现虚构 Mock 数据，旁白没有“真实业务验证”或“显著提升”等无证据表述。
- 点击、加载、版本切换和异常状态均完整可见，字幕没有遮挡关键 UI。
- 导出后从头播放一遍，并在另一台设备验证视频与 Demo 链接可访问。
