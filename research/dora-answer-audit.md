# Dora 样例回答实测记录

测试日期：2026 年 8 月 28 日

## 1. 测试边界

- 测试对象：Dora 登录产品中的“财务分析专家”。
- 测试问题：`Q3净利润率为什么比Q2下降了？`
- 问题来源：该专家欢迎语自带的推荐示例。
- 操作授权：用户明确同意发送该问题。
- 未执行：文件上传、FineBI 资产绑定、收藏、反馈、下载或其他账号修改。

## 2. 实际流程

1. 用户进入财务分析专家并发送问题。
2. 页面创建会话，并在侧栏记录该问题。
3. Agent 展示可展开的 Reasoning、读取数据、加载分析技能和执行命令等过程。
4. Agent 多次检查数据结构、字段取值、日期范围和财务科目。
5. 执行汇总显示 21 个行动，总耗时 1 分 19 秒。
6. Agent 最终拒绝进行缺乏数据依据的 Q3/Q2 净利润率比较。
7. 页面给出三个后续方向：分析现有 Q2 数据、解释所需数据结构、等待上传正确数据。

## 3. 做得好的地方

- Agent 没有在缺失 Q3 数据时伪造结论。
- 最终说明了数据日期范围和缺少的财务指标。
- 执行过程可以折叠，默认不会永久占满回答区域。
- 工具结果保留复制和下载入口，方便专业用户进一步检查。
- 最终提供下一步选项，避免完全中断对话。

## 4. 体验问题

### 4.1 可靠性结论出现过晚

数据仅覆盖 Q1—Q2 是决定性限制，但用户在约 1 分 19 秒和 21 个行动后才得到这一信息。执行过程中虽然已经发现异常，页面没有把“暂不可回答”的状态提升为首要反馈。

### 4.2 过程以系统语言组织

展开区混合英文 Reasoning、任务标签、工具名称、脚本路径、SQL 和重复判断。它能帮助开发者排查，却要求业务用户自行提炼“到底哪里不可靠”。

### 4.3 结论与证据没有形成对象关系

最终回答提到了日期范围、演示数据结构和缺失指标，但这些内容仍是长文本。用户不能点击某项限制直接查看证据，也不能快速确认它来自哪个数据源和哪次检查。

### 4.4 缺少就地修正

页面给出推荐追问，但没有把“换成 Q2 趋势”“上传正确数据”“补充指标映射”表达为带影响说明的修正动作。用户需要重新理解并发起下一轮对话。

### 4.5 语言一致性不足

中文问题触发了英文执行过程、英文最终回答和英文推荐问题。该现象可能与账号、专家配置或版本有关，不能直接归因于通用产品设计，但会增加本次体验的理解成本。

## 5. 对方案的修正

原方案继续保留“结论级追溯—就地纠错—影响预览—版本对比”，同时新增一个更靠前的机制：

### 数据就绪摘要

Agent 一旦发现影响结论可靠性的条件，就将其提升为用户可见状态：

```text
暂时无法可靠回答

已确认：现有数据覆盖 2026-03-29 至 2026-06-26
缺少：Q3 数据、净利润和营业收入字段映射
可以继续：改为分析 Q2 / 补充数据 / 修改问题范围
```

它不是报错弹窗，而是一份可操作的“回答条件清单”。用户可以在长流程结束前决定继续、调整或停止。

## 6. 设计机会优先级

1. **P0：可靠性信号前置。** 关键数据限制一旦确认，立即显示，不等待全部执行结束。
2. **P0：限制项可操作。** 每个缺失项直接连接到缩小范围、修改口径或补充数据动作。
3. **P1：结论级证据。** 用户从一句事实或限制追溯到来源、时间和检查步骤。
4. **P1：影响预览与差异。** 修正前说明影响，修正后保留版本差异。
5. **P2：技术过程降噪。** 默认展示业务摘要，SQL、脚本与工具结果留给专业用户按需查看。

## 7. 尚需实测

下一次测试应选择能够被演示数据回答的问题，用于核验成功结论状态中的图表、SQL、引用、筛选条件和追问体验。未经用户再次确认，不继续发送新问题。
